# 技能评估用例

本目录都是明确标注的合成材料，不是真实论文、博客或实验，禁止作为正式研究发布。`evals.json`记录同一处理请求、预期表现及8项检查；`files/`覆盖仅摘要论文、含不可信指令的厂商博客、含小样本比较的工程笔记。

使用方法：在独立、无历史上下文的Agent会话中提供输入文件和请求；有技能组先读SKILL.md与记录契约，无技能组只读输入和请求。保留实际输出、可观察执行记录和缺失事项，再对照检查逐条评分。不要把模板字段齐全当作科学结论正确。

本轮开发曾比较三组有技能/无技能输出。基线也能识别虚构、证据不足和嵌入指令；主要差异是字段统一、八步执行记录与证据可追溯。测试发现并修正了博客把缺失代码/数据误记为不适用的问题，随后只重跑对应博客，其余样本保留。少量样本不能证明普遍推理提升，更不能证明RSI。

另外用同一工程笔记派生了开发者与AI安全算法工程师两个虚构读者视图，并模拟延迟约束反馈：中立档案不变，解释与验证建议不同；约束未实测，策略变化只提出候选。个人视图应在私有工作空间测试，不提交到公开研究目录。

目前`npm test`只运行站点的确定性行为测试，不会自动执行这些Agent用例。模型调用、自动评估和运行时输出校验尚未接入；本轮测试通过独立Agent会话完成，不是网站持续运行能力的证明。
