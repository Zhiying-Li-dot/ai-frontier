# 研究 Agent 与个人持续改进

## 产品目标

系统帮助每个人理解前沿 AI 技术、用于日常工作，再根据本人的反馈逐步改善服务。初始角色包括开发者、Agent工程师、AI算法工程师、AI安全算法工程师。同一工种的两个人也可能需要不同选材、解释深度与工作建议；岗位模板只是起点，个人确认的目标与知识状态优先。

当前RSI目标分两层：改进服务这个人的策略，再检验“如何生成有效改进”的方法是否也变得更好。建立skill或收集反馈不等于已经实现这两层效果。

## 两条相连的工作流

```text
公开资料 → 发现候选 → technical-content-reading skill
  → 中立研究档案 → 事实与发布复核 → 共享研究内容

共享研究 + 本人确认的私有目标/知识/约束
  → 个人策略 → 解释 + 日常工作中的小规模验证建议
  → 反馈 + 实际使用结果 → 候选策略变化
  → 独立案例对照 → 采用或拒绝 → 下一次交互
```

这些是职责划分，不要求每个方框都调用一个独立模型。首个执行器可以是一个拥有明确步骤、状态和工具的Agent；评估与发布仍保留单独边界。

## 阅读能力

所有待研究收录的论文、博客、报告、文档、代码仓库等技术资料，都使用[technical-content-reading](../skills/technical-content-reading/SKILL.md)，产出[统一研究记录](../skills/technical-content-reading/references/record-contract.md)。资料类型改变核查重点；博客不需要虚构的论文式附录，论文摘要也不能成为全文精读。

发现阶段可以把题录保留在候选列表，无须假装已经读过。只有实际研究处理才记录skill执行。现有档案保留其真实历史，不补造此前不存在的技能执行记录。

## 个人策略

分别维护四个有版本的对象：

| 对象 | 作用 | 可见范围 |
| --- | --- | --- |
| 共享研究档案 | 来源身份、证据、适用条件和未决问题 | 复核后可公开 |
| 使用者上下文 | 本人确认的目标、主题知识、任务约束与偏好 | 仅本人 |
| 个人策略 | 选材、解释、追问和工作建议规则 | 私有；可从岗位模板开始 |
| 改进策略 | 诊断反馈、生成候选个人策略的方法 | 受控、有版本；使用公开或另行获准的数据 |

个性化解释引用同一来源版本、证据ID和实际采用的策略版本。可以改变例子和深度，不能改变事实。例如开发者可能先看接入与测试，算法工程师可能先看推导与实验；证据边界始终一致。

记忆变化应可查看、更正和删除。推断的新偏好需要本人确认；不回复或停留时间较长不等于同意。岗位或任务变化可能使旧偏好失效，因此记录确认日期与适用范围。

## 从反馈到候选改进

1. 记录相关的用户可见产出、来源与证据引用、策略版本，以及可选反馈。
2. 区分知识缺口、深浅不合适、相关性不足、遗漏约束、事实问题和实际工作结果。
3. 每次提出一项有限变化，写清旧/新策略、原因、适用主题与预期改善。
4. 用另外的相关案例或后续任务对照旧策略，保持证据质量和成本边界，记录正面、负面和无法判断的结果。
5. 本人可检查并接受记忆/策略变化，保留回退；未测试或失败的候选不静默替换当前策略。

事实错误交共享证据复核；偏好只影响对应个人。使用效果记录条件与基线，“喜欢”不等于“实际用过且有效”。业务建议在真实试点前始终标为未验证。

## 评估与受控RSI

分别衡量理解、相关性、技术正确性、建议可行性、实际工作收益、成本和延迟。满意度只是一个信号，不单独优化点击、阅读时长或称赞；表达更轻松不能弥补证据变弱。

调优案例与冻结验收案例分开。旧/新策略在相同模型与预算下比较，使用公开合成或另行获准的案例，不借用别人的原始私人对话。候选可以修改阅读和解释策略，不能修改评分规则、发布条件、权限、凭证或费用上限。

后续对照两个改进策略：在相同个人策略起点和资源下，哪一个产生的后代更能帮助使用者完成独立任务？跨轮重复验证后再报告递归改进。如果只测得个人任务表现改善，就报告这一实际结果，不把更强结论当作已证明。

## 隐私与执行边界

个人档案、原始对话、个性化视图、业务材料和反馈不进入公开cloud-data/、public/、研究提交或技能评估上传。跨人复用需要另行明确合法依据和告知，优先使用经审阅、去标识化的失败类型。用户删除同时删除或排除关联派生记忆与未来评估样本。

初始范围仅包括公开或明确获准的非敏感材料。不收集隐藏思维链，不接入公司机密材料，不自动执行业务系统操作。私人持久化和外部模型处理需要单独核实保护措施、实际地点、保留与删除安排。启用个人信息处理前，单独判断实际处理、自动化决策或第三方关系是否触发个人信息保护影响评估；命中时先完成适用评估，再开放对应处理。个人项目不假定公司专用网关或审批已接入。

在服务、凭证与明确金额上限配置前，新模型任务保持禁用。失败调用也计入限额，改进循环不能提高自身预算或自动切换服务商。发布、共享私人材料和实际业务操作分别需要相应授权。

## 本轮已落地与后续工作

- 仓库skill、资料类型路由、中立输出契约和个人适配参考。
- [AGENTS.md](../AGENTS.md)为参与研究收录的Agent提供调用与交接规则。
- 论文摘要、厂商博客和工程笔记合成案例支持重复评估，不作为真实研究发布。

本轮落地的是Agent能力及接入约定，不是自动运行钩子。现有GitHub Actions仍只做来源发现和静态发布。Markdown文件没有接通模型阅读执行器、私人画像/反馈存储、新记录的运行时发布校验、自动策略采用或RSI实验。下一项可执行开发应是阅读执行器加记录校验/发布交接，保留既有档案并验证后再启用；随后才是私人状态、反馈循环和受控改进实验。
